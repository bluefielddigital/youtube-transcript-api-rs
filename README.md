A Rust library and command-line tool for fetching the transcripts and
subtitles of YouTube videos, including automatically generated ones. It
needs no API key and no headless browser.

The repository is a Cargo workspace with two crates, released together at
one version:

- [`youtube-transcript-api`](crates/youtube-transcript-api): the library.
- [`youtube-transcript-api-cli`](crates/youtube-transcript-api-cli): the
  command line, which installs the `youtube-transcript-api` program.

Inspired by Jonas Depoix's
[youtube-transcript-api](https://github.com/jdepoix/youtube-transcript-api)
for Python. The command line takes the same options, plus a few more, and
writes the same formats, so scripts written for the Python tool work
unchanged.

## Features

- Fetch a transcript by video ID or any YouTube URL (`watch`, `youtu.be`,
  `shorts`, `embed`, `live`), in the first of your preferred languages that
  has one: manual or generated by YouTube. With language variants on, `en`
  also finds `en-US` and `en-GB`.
- List every transcript a video has, and translate one into any language
  YouTube offers.
- Video details at no extra cost: title, author, channel, length,
  views, likes, description, keywords, category, publish date, and thumbnails.
- Output as plain text (with or without timestamps), SRT, WebVTT or JSON,
  or in YouTube's own formats (srv1/srv2/srv3, json3, TTML, WebVTT), whose
  srv3 and json3 have per-word timing for generated captions.
- Proxies: any HTTP, HTTPS or SOCKS5 proxy, or Webshare's rotating
  residential proxies with automatic retries when YouTube blocks a request.
- Async on tokio. Set request timeouts, or plug in your own HTTP client.
- A command-line tool, as one self-contained binary for Linux, macOS and
  Windows.
- Transcripts and video details serialize with `serde`.

## Installation

### Library

```bash
cargo add youtube-transcript-api
cargo add tokio --features macros,rt-multi-thread
```

The library has no command-line dependencies: the command line is a separate
crate.

### Command line

Download a binary for your platform from the [releases page][releases].
Each release has a `SHA256SUMS` file to check it against.

The macOS binaries carry a Developer ID signature and Apple's notarization,
so they run without a Gatekeeper warning. macOS checks the notarization online
the first time one runs.

Or build it with Cargo:

```bash
cargo install youtube-transcript-api-cli
```

Either way, you run `youtube-transcript-api`.

TLS comes from rustls on Linux and macOS, and from the system's own TLS
(SChannel, through native-tls) on Windows. rustls needs a C compiler and
CMake to build its cryptography library, which Windows build machines often
lack. SChannel needs neither and uses the Windows certificate store.

## Usage

Pass a video ID, such as `dQw4w9WgXcQ`, or any YouTube URL for the video:
`https://www.youtube.com/watch?v=dQw4w9WgXcQ`, `https://youtu.be/dQw4w9WgXcQ`,
or a `shorts`, `embed` or `live` link. `video_id()` does the same
extraction on its own.

Runnable versions of these examples are in
[`examples/`](crates/youtube-transcript-api/examples). Run one with:

```bash
cargo run -p youtube-transcript-api --example fetch -- dQw4w9WgXcQ
```

### Fetch a transcript

```rust
use youtube_transcript_api::YouTubeTranscriptApi;

#[tokio::main]
async fn main() -> Result<(), youtube_transcript_api::Error> {
    let api = YouTubeTranscriptApi::new()?;

    // German if there is one, otherwise English.
    let transcript = api.fetch("dQw4w9WgXcQ", &["de", "en"], false).await?;
    for snippet in &transcript {
        println!("{:>8.2}  {}", snippet.start, snippet.text);
    }
    Ok(())
}
```

Each snippet has its `text`, its `start` and its `duration` in seconds.
Passing `true` as the last argument keeps HTML formatting tags such as `<i>`
and `<b>` in the text.

### List, choose, and translate

```rust
let list = api.list("dQw4w9WgXcQ").await?;
for transcript in &list {
    println!(
        "{} {} generated={}",
        transcript.language_code, transcript.language, transcript.is_generated
    );
}

// Any transcript, manually created ones first...
let english = list.find_transcript(&["en", "en-US"])?;
// ...or only one kind.
let manual = list.find_manually_created_transcript(&["en"])?;
let generated = list.find_generated_transcript(&["en"])?;

// Translate before fetching.
if english.is_translatable() {
    let german = english.translate("de")?.fetch(false).await?;
}
```

Language codes match exactly by default. To let `en` also find `en-US` or
`en-GB` (and `en-GB` find `en`) when there's no exact match, turn on
variants for the whole client, or for one list:

```rust
let api = YouTubeTranscriptApi::builder().match_language_variants(true).build()?;
let list = api.list("dQw4w9WgXcQ").await?.match_language_variants(true);
```

### Video details

The list carries the video's details, from responses it downloads anyway:

```rust
let list = api.list("dQw4w9WgXcQ").await?;
if let Some(details) = list.video_details() {
    println!("{:?} by {:?}", details.title, details.author);
    println!("{:?} seconds, published {:?}", details.length_seconds, details.publish_date);
}
```

Every field YouTube may leave out is an `Option`.

### Output formats

```rust
use youtube_transcript_api::formatters::{Formatter, SrtFormatter};

let transcript = api.fetch("dQw4w9WgXcQ", &["en"], false).await?;
std::fs::write("rick.srt", SrtFormatter.format_transcript(&transcript))?;
```

| Formatter | Output |
|---|---|
| `TextFormatter` | The text, one snippet per line |
| `TimestampedTextFormatter` | `[01:23] text`, or `[01:02:03] text` past an hour |
| `SrtFormatter` | SRT subtitles |
| `WebVttFormatter` | WebVTT subtitles |
| `JsonFormatter` | Compact JSON: an array of `{text, start, duration}` |
| `PrettyPrintFormatter` | The same JSON, indented |

`format_transcripts` formats a list of transcripts as one string.

### YouTube's own formats

`fetch_raw` returns a transcript exactly as YouTube sends it, in one of its
formats. `Srv3` and `Json3` include per-word timing for generated captions.

```rust
use youtube_transcript_api::RawFormat;

let list = api.list("dQw4w9WgXcQ").await?;
let generated = list.find_generated_transcript(&["en"])?;
let srv3 = generated.fetch_raw(RawFormat::Srv3).await?;
```

| `RawFormat` | What YouTube sends |
|---|---|
| `Srv1` | XML, one element per caption, times in seconds |
| `Srv2` | XML, times in milliseconds |
| `Srv3` | XML with per-word timing for generated captions |
| `Json3` | JSON with per-word timing for generated captions |
| `Ttml` | TTML (Timed Text Markup Language) |
| `Vtt` | WebVTT |

## Command line

```bash
# The English transcript, as indented JSON.
youtube-transcript-api dQw4w9WgXcQ

# Two videos, by ID or URL, German or else English, as SRT.
youtube-transcript-api dQw4w9WgXcQ https://youtu.be/jNQXAC9IVRw --languages de en --format srt

# With timestamps, giving up on a request after 30 seconds.
youtube-transcript-api dQw4w9WgXcQ --format timestamped-text --timeout 30

# YouTube's own JSON, with per-word timing for generated captions.
youtube-transcript-api dQw4w9WgXcQ --exclude-manually-created --raw json3

# What's available.
youtube-transcript-api --list-transcripts dQw4w9WgXcQ

# Translated, through a Webshare proxy.
youtube-transcript-api dQw4w9WgXcQ --translate de \
  --webshare-proxy-username USER --webshare-proxy-password PASS
```

| Option | Meaning |
|---|---|
| `--languages CODE…` | Language codes to try, in order (default `en`) |
| `--match-language-variants` | Let `en` also find `en-US`, and `en-GB` find `en` |
| `--format FORMAT` | `pretty` (default), `json`, `text`, `timestamped-text`, `srt` or `webvtt` |
| `--raw FORMAT` | YouTube's own format instead: `srv1`, `srv2`, `srv3`, `json3`, `ttml` or `vtt` |
| `--preserve-formatting` | Keep HTML formatting tags such as `<i>` in the text |
| `--list-transcripts` | List the available transcripts instead |
| `--translate CODE` | Translate the transcript into this language |
| `--exclude-generated` | Only manually created transcripts |
| `--exclude-manually-created` | Only generated transcripts |
| `--timeout SECONDS` | Give up on a request after this long |
| `--http-proxy URL`, `--https-proxy URL` | Use these proxies |
| `--webshare-proxy-username`, `--webshare-proxy-password` | Use Webshare |

Transcripts go to stdout and errors to stderr. The exit code is 1 if any
video failed. To pass an ID that starts with `-`, escape it: `\-abc`.

## Requirements

- Rust 1.88 or newer, to build.
- A tokio runtime, for the library.

## Limits

- **No API key.** The library reads the same pages and endpoints as the
  YouTube website and the Android app. Nothing to register, and no quota
  to buy.
- **YouTube limits requests.** Too many from one IP get HTTP 429 or a bot
  check, which shows as `IpBlocked` or `RequestBlocked`. YouTube blocks hosting
  provider IPs most. See [Proxies](#proxies).
- **Translation draws more rate limits.** Asking for a translation
  (`translate`, `--translate`) often draws a 429 while the original
  transcript still downloads. Use a rotating proxy for translations.
- **Retries and backoff.** Without a proxy, nothing retries. A proxy config
  turns retries on, and `RetryPolicy` sets a count of your own. Each retry
  waits a random time under a ceiling that starts at 500 ms and doubles up
  to 30 s. A 429 with a `Retry-After` up to 60 s waits that long instead.
  If the server asks for more, the request fails at once with
  `TransportErrorKind::RateLimited`, and `TransportError::retry_after` holds
  the wait, so your code can wait and try again. Set the policy with
  `YouTubeTranscriptApi::builder().retry_policy(..)`.
- **Response size.** The built-in client rejects a response body over 16 MiB
  (`max_body_bytes` changes it). A watch page is 1 to 3 MB.

For causes and fixes, see [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## Advanced usage

### Proxies

YouTube blocks requests from most cloud providers' IPs (AWS, GCP, Azure,
and others). From a server, route requests through a proxy.

Rotating residential proxies from [Webshare](https://www.webshare.io/) suit
this: each request gets a new IP, and a blocked request tries again with
another, up to 10 tries by default.

```rust
use youtube_transcript_api::YouTubeTranscriptApi;
use youtube_transcript_api::proxies::WebshareProxyConfig;

let proxy = WebshareProxyConfig::new("username", "password")
    .with_filter_ip_locations(["us", "gb"]) // only IPs in these countries
    .with_retries_when_blocked(5);
let api = YouTubeTranscriptApi::builder().proxy_config(proxy).build()?;
```

Or any HTTP, HTTPS, or SOCKS5 proxy. With `socks5h://`, the proxy also
resolves host names.

```rust
use youtube_transcript_api::proxies::GenericProxyConfig;

let proxy = GenericProxyConfig::new(Some("http://user:pass@host:8080".into()), None)?;
let api = YouTubeTranscriptApi::builder().proxy_config(proxy).build()?;
```

### Timeouts

There's no timeout by default, and a stalled proxy or connection can hang a
request indefinitely. Set one for each request, from sending it to reading
the whole response:

```rust
use std::time::Duration;

let api = YouTubeTranscriptApi::builder()
    .timeout(Duration::from_secs(30))
    .build()?;
```

A request that times out counts as failed, so with a proxy that retries
(such as Webshare's), it's retried through another IP.

### Your own HTTP client

Requests go through the `HttpClient` trait. The default, `ReqwestClient`,
uses reqwest with rustls (the system TLS on Windows). Write your own to use
another client, add logging or caching, or run tests without the
network:

```rust
use std::sync::Arc;

let api = YouTubeTranscriptApi::builder()
    .http_client(Arc::new(MyClient::new()))
    .build()?;
```

A client answers each `HttpRequest` with `HttpResponse::new(status, url,
headers, body)`, or a `TransportError::new(kind, message)` when the request
never got an HTTP response.

### Logging

With the `tracing` feature, the crate emits [`tracing`](https://docs.rs/tracing)
events under the `youtube_transcript_api` target: each request and its
status at `DEBUG`, each retry with its cause and wait at `INFO` (including a
rotating proxy's retry through a new IP when YouTube blocks one), and
accepting YouTube's cookie consent page at `DEBUG`. Without the feature,
there is no `tracing` dependency and no cost.

```bash
cargo add youtube-transcript-api --features tracing
```

Any `tracing` subscriber shows them, for example `tracing-subscriber` with
`RUST_LOG=youtube_transcript_api=debug`.

## Error handling

A failed fetch is an `Error::CouldNotRetrieveTranscript`, whose `reason` says
why. Its message explains the likely cause and what to try.

```rust
use youtube_transcript_api::{Error, Reason};

match api.fetch(video_id, &["en"], false).await {
    Ok(transcript) => println!("{} lines", transcript.len()),
    Err(Error::CouldNotRetrieveTranscript(error)) => match &error.reason {
        Reason::NoTranscriptFound { .. } => println!("No English transcript"),
        Reason::TranscriptsDisabled => println!("Transcripts are disabled"),
        reason if reason.is_request_blocked() => println!("Blocked: use a proxy"),
        _ => println!("{error}"),
    },
    // Network failures, proxy configuration, unexpected responses.
    Err(other) => println!("{other}"),
}
```

| `Reason` | Meaning |
|---|---|
| `NoTranscriptFound` | None in the requested languages |
| `TranscriptsDisabled` | The video has no transcripts |
| `NotTranslatable`, `TranslationLanguageNotAvailable` | The translation isn't offered |
| `VideoUnavailable`, `VideoUnplayable` | The video doesn't play |
| `InvalidVideoId` | A URL that isn't a YouTube video link |
| `AgeRestricted` | Age-restricted videos need a signed-in user, which isn't supported |
| `RequestBlocked`, `IpBlocked` | YouTube is blocking your IP |
| `PoTokenRequired` | YouTube wants a proof-of-origin token for this video |
| `YouTubeRequestFailed`, `YouTubeDataUnparsable`, `FailedToCreateConsentCookie` | Something unexpected came back from YouTube |
